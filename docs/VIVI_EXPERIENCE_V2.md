# Vivi Experience V2 — архитектура

Ветка `quality/vivi-experience-v2`, от `04b3ff2` (compiler hardening v1).
Отчёт о проверках: [`reports/experience-v2-qa.md`](../reports/experience-v2-qa.md).

Цель билда — не новая игровая механика, а короткий человеческий опыт:

> понять ситуацию → почувствовать трудность → посмотреть на значимое →
> совершить поступок → увидеть его исполнение → узнать, что сделал автор →
> захотеть рассказать своё.

Пайплайн прежний: `рассказ → семантическая модель → компактный DSL →
детерминированный компилятор → сохранённая сцена`. Во время игры модель не
вызывается. Экспериментального «отдельного демо-рантайма» нет: три редакционных
эпизода, сгенерированные посты, старые посты и курируемые демо идут через один
и тот же `compileViviStory` → `CanonicalViviEngine` → `ViviPlay`.

---

## 1. Что добавлено к DSL (минимально, версионно)

Два необязательных поля. Программы без них остаются валидными и компилируются
как раньше.

| поле | что это | кто решает |
|---|---|---|
| `m.d` | момент решения — что герой должен решить сейчас | модель, из рассказа |
| `m.h` | почему это трудно | модель, из рассказа |
| `m.k` | до 4 фактов, которые герой знает в этот момент | модель, из рассказа |
| `m.f` | `play` или `memory` (решать было нечего) | модель |
| `ob` | 0–3 «посмотреть» без последствий: `[цель, что видно, подпись?]` | модель, из рассказа |

В commitments (`a`) модель больше не пишет `observation`/`outcome` —
сгенерированный «следующий момент» мог содержать выдуманную реакцию другого
человека. Поля остались в формате для совместимости.

Контракт (`modelContract.ts`, `structuredContract.ts`) явно говорит: открыть
чужую переписку — поступок, а не взгляд; не выдумывать ответ, второе сообщение,
звук, приход человека, чью-либо реакцию. Если модель не назвала момент,
существующий единственный repair-ход просит его (или `m.f = memory`).

## 2. Слой ситуации — `src/engine/experience/`

| файл | ответственность |
|---|---|
| `types.ts` | `ExperienceV2`: формат, недостающая информация, момент, трудность, факты (с источником), наблюдения, поступки, рецепт исполнения, граница |
| `boundary.ts` | граница «до решения / после решения», поиск источника факта в предложениях автора, проверка первого лица (RU/EN/HY) |
| `meaning.ts` | смысл поступка (`look_private`, `address`, `speak_public`, `withdraw`, `hold`, `secure`, `open_up`, `give_back`, …) и способ исполнения; разнообразие считается по смыслу, а не по типу цели |
| `situation.ts` | `buildSituation` (сверка с текстом автора) и `assessFormat` (format gate) |
| `interaction.ts` | interaction resolver и семантическая доступность |
| `machine.ts` | чистая машина состояний опыта, эффекты вместо побочных действий |
| `enactment.ts` | рецепты исполнения и `enactmentScript` — единственный источник текста после поступка |
| `hotspots.ts` | группировка намерений по целям в комнате |
| `playback.ts` | «запечатанное» раскрытие и явный адаптер старых сцен |
| `choiceStore.ts` | локальный первый выбор (идемпотентно, по версии сцены, повторы отдельно) |
| `copy.ts` | интерфейсные строки RU/EN/HY |

### Что решает модель, что — движок

| Модель (по тексту автора) | Детерминированный движок |
|---|---|
| момент решения, известные факты, трудность | координаты, точки стояния, маршруты |
| что можно рассмотреть и что там видно | камера, инсерты, крупность |
| 2–4 поступка | исполнение поступка, жесты, тайминг |
| мир, грамматика, кто есть в комнате | свет, звук, граница сцены, переход к раскрытию |
| `play` / `memory` | формат по недостающей информации, вопрос автору |

Произвольных runtime-скриптов от модели нет; движок не вызывает модель.

### Честность фактов

* В модель и в repair уходит только текст **до** решения. Если автор вписал
  развязку в сам рассказ, `compileViviStory` применяет ту же границу, что видит
  автор, и не отправляет её (тест с канарейками в запросах first pass и repair).
* Каждый факт и каждое наблюдение сверяются с предложениями автора; не
  найденное помечается `unsourced` и показывается автору в предпросмотре.
* «Открыть сообщение» показывает только текст, который рассказ цитирует.
* Постановка V2 не добавляет то, чего нет в рассказе: нет таймера блокировки
  телефона, нет счётчика этажей лифта, нет «времени» на офисных часах, нет
  ноутбука, если его нет в истории, индикатор домофона не горит без звонка.
* Автоматическая сверка — это эвристика по словам, **не гарантия** фактической
  верности. Поэтому есть предпросмотр с «убрать / верно».

## 3. Format gate

`assessFormat` называет, чего не хватает, а не выдаёт «уверенность»:

| не хватает | формат | вопрос автору (один) |
|---|---|---|
| — | `playable` | — |
| перспектива («я») | `text_story` | — |
| момент решения | `illustrated_memory` | «В какой момент нужно было решить?» |
| трудность | `illustrated_memory` | «Почему было трудно решить?» |
| < 2 разных по смыслу поступков | `illustrated_memory` | «Что ещё ты мог(ла) сделать?» |
| поступок автора | `illustrated_memory` | «Что ты сделал(а)?» |

Детерминированный fallback не умеет читать рассказ, поэтому никогда не
становится игрой с выдуманной драмой — он честно уходит в воспоминание.

## 4. Управление: intent first

* Цели — настоящие `<button>` в мире (Tab-порядок, 44 px, компенсация зума).
  Намерения группируются по цели: «Посмотреть на экран» и «Открыть переписку»
  живут на одном телефоне; «ждать» и «сказать вслух» — на самом герое.
* Панель под сценой (не поверх) называет конкретное действие; подсказка
  соответствует текущему вводу (мышь / касание / клавиатура).
* «Что я могу сделать?» — все намерения, существующие в комнате, и только они.
* **Resolver**: на месте → подход к авторской точке → ближайшая достижимая точка
  у цели (≤ 12 ед.) → монтажная склейка → текстовое исполнение. Отказа по
  расстоянию нет. Диагностика пишется в консоль (dev) и телеметрию (режим).
* Смысл может отказать: отсутствующий человек не появляется; за закрытой
  дверью к нему можно обратиться через дверь.
* Свободное перемещение (клавиши, тап по полу) — необязательно. Джойстика нет.

## 5. Observation ≠ commitment

```
orienting → exploring ⇄ approaching → observing → exploring
                │  выбрать поступок (pending, можно отменить)
                ▼
             COMMIT → enacting → pausing → boundary → revealed
```

* Наблюдение никогда не фиксирует выбор и не запускает исполнение.
* Поступок — два явных шага: выбрать → «Сделать это». Модального окна на
  каждое наблюдение нет.
* После фиксации: выбор сохраняется ровно один раз, остальные поступки
  закрыты, отменить нельзя, **мир останавливается** (никто не двигается, не
  говорит, не приходит), герой исполняет поступок, пауза, сцена уходит в
  бумагу, затем раскрытие. Reveal не начинается раньше конца исполнения или
  явного «Пропустить».
* Reduced motion: склейки вместо ходьбы, короткие паузы.

## 6. После выбора

* Показывается выбранный поступок, а не ответ: «Спросить» — герой говорит у
  двери, ответа нет; «Уйти» — герой уходит; «Открыть сообщение» — только
  цитируемый текст. Пометки: «Что ответили — в этой истории не сказано», «На
  этом сцена останавливается».
* Раскрытие: «Ты выбрал(а)…» → «А я…» → почему → что было потом (только если
  автор это написал) → «Это то, как поступил один человек, — не правильный
  ответ».
* Финал: «Почему я выбрал(а) так» (заметка только на этом устройстве), «У меня
  было похоже» (существующий `responseToPostId`), связанная история — только
  если такая связь действительно есть. Никаких выдуманных счётчиков, процентов
  и откликов; честный пустой стейт.

## 7. Граница pre-reveal payload — точное ограничение

`sealForPlayback` отделяет сцену (то, что получают сцена, камера, панель и
меню) от запечатанного раскрытия; сцена не содержит поступка автора (тест).
**Но в этом стеке все посты хранятся в localStorage автора, а демо-истории
собраны в клиентский бандл.** Значит, это структурная граница внутри одного
клиента, а не защита от чтения payload. Настоящая граница требует серверного
хранения постов и выдачи раскрытия только под записанный выбор
(`POST /api/posts/:id/choice` → `GET /api/posts/:id/reveal`) — это не сделано,
потому что у продукта сейчас нет ни серверных постов, ни аккаунтов.

## 8. Совместимость

* Старые посты (DSL без `m`/`ob`) не перекомпилируются и не меняются: при
  загрузке их сцена проходит через явный `experienceFor` (`origin:
  'legacy_adapter'`): каждое старое действие → одно «посмотреть» и один поступок.
  Сгенерированный старый «следующий момент» не показывается (мог содержать
  выдуманную реакцию). Тест сравнивает пост до и после адаптации побайтно.
* `COMPILER_VERSION` 1.0.0 → 1.1.0. Правила V2 (нет выдуманных таймеров, вещь в
  лифте на полу кабины, два поступка у одной вещи остаются у неё) действуют
  только для сцен с ситуационным слоем.

## 9. Как запустить

```bash
npm install
npm run lint && npm test && npm run build

# Без живой модели: сохранённые редакционные программы + детерминированный fallback
SEMANTIC_PROVIDER=replay PORT=3011 npx tsx server.ts
# → http://localhost:3011
```

* Лента → «Редакционные эпизоды · Experience V2» → любой из шести.
* Напрямую (только dev): `?play=v2-apartment-ru`, `?play=v2-office-ru`,
  `?play=v2-hallway-ru`, `?play=v2-hallway-memory-ru`, `?play=v2-apartment-en`,
  `?play=v2-hallway-hy`.
* Create → вставьте текст фикстуры (`src/data/experienceFixtures/index.ts`,
  поле `source`), можно с припиской развязки («В итоге я…») — replay-провайдер
  ответит сохранённой программой; любой другой текст пойдёт через
  детерминированный fallback.
* С живой моделью: обычный `npm run dev` с `OPENROUTER_API_KEY` и
  `OPENROUTER_MODEL` в `.env` (в этом билде живые вызовы не делались).
* Телеметрия для QA (dev): `window.__viviTelemetry.getSession()` в консоли —
  только id и режимы, без текстов и без поступка автора.
* Только тесты V2: `npm run test:v2`.
